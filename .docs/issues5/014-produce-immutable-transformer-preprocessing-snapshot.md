# Ticket 014: Produce an immutable Transformer Preprocessing Snapshot

## What to build

Provide one lazily initialized, application-wide Transformer Preprocessing Snapshot derived only from the fixed Transformer Training Corpus. Preserve the TypeScript Reference Implementation's corpus order, Transformer-specific BPE behavior, tokenization, ordered Vocabulary, token IDs, Training Sequences, generation seed IDs, and exactly four Logical Training Shard boundaries.

The completed snapshot must be safe to reuse across sequential and concurrent Transformer Training Runs. Publication is all-or-nothing: a failed construction attempt leaves no partial global value, and a later caller may retry successfully.

## Acceptance Criteria

- [ ] The snapshot preserves every fixed Transformer Training Corpus story and its exact order from the TypeScript Reference Implementation.
- [ ] The BPE training text, merge-learning behavior, Pre-token boundaries, ordered Merge Table, and ordered merge application match independent reference fixtures.
- [ ] Tokenized stories preserve exact token order and never merge across Pre-token boundaries.
- [ ] Vocabulary Tokens preserve the approved deterministic ordering, and every token maps to exactly one stable integer ID.
- [ ] The complete token-ID stream matches the independently captured reference fixture.
- [ ] Transformer Training Sequences use fixed length `16`, preserve input and next-token target order, and match exact fixture counts and representative sequences.
- [ ] Generation seed IDs are exactly the first three IDs from the complete corpus-derived token stream.
- [ ] Exactly four Logical Training Shard boundaries are calculated from the ordered Training Sequences using `ceil(sequence_count / 4)` and contiguous slices.
- [ ] Shard identity and boundaries do not depend on CPU count, operating-system worker count, request parameters, or completion order.
- [ ] An empty trailing shard is represented deterministically when a small test snapshot contains fewer sequences than shards.
- [ ] The public snapshot contains the corpus, Merge Table, tokenized stories, ordered Vocabulary, token indices, complete token-ID stream, Training Sequences, generation seed IDs, and four shard boundaries with no request-owned or mutable training state.
- [ ] Nested public values are immutable or read-only so mutation through one caller cannot affect later or concurrent callers.
- [ ] Initialization uses double-checked access guarded by one module-local thread lock and returns the same fully published logical snapshot to concurrent callers.
- [ ] A controlled construction failure publishes nothing, releases the initialization path, and allows a later call to retry and publish a complete snapshot.
- [ ] Request fields including epochs, temperature, topP, numLayers, and maxTokens do not alter any preprocessing artifact.
- [ ] Expected corpus, Merge Table, tokenization, Vocabulary, token IDs, sequence boundaries, and shard boundaries are fixed independent evidence rather than values generated by the production operation under test.

## Testing Expectations

- **Approved test seam:** The stable public Transformer preprocessing boundary, including controlled concurrent initialization and failure-retry tests.
- **Behavior to verify:** Exact corpus and BPE artifacts, ordered Vocabulary and token IDs, Training Sequences, seed IDs, four Logical Training Shards, immutability, double-checked lazy publication, all-or-nothing failure behavior, and request independence.
- **Relevant prior art:** The completed reusable BPE tests and the immutable Word2Vec preprocessing pattern, adapted only where the Transformer reference path differs.
- **Do not test through:** Private cache identity, helper names, a specific frozen-container type, lock implementation internals, or worker-process behavior.

## Blocked By

- None — can start immediately.

## Constraints and Out of Scope

- Reuse the established BPE boundary where it matches the Transformer reference behavior; do not fork an unnecessary tokenizer implementation.
- Do not accept request text, seed text, Query Words, or generated samples as training data.
- Do not add a mutable preprocessing cache, disk cache, request-specific snapshot, configurable corpus, or configurable shard count.
- Do not initialize weights, execute Transformer mathematics, start processes, persist models, or expose an HTTP route in this ticket.
- Do not change frontend code.
- No new dependency or lockfile change is expected.
